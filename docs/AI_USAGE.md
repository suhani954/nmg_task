# AI usage

Codex was used through the user's desktop coding assistant for reading the brief, planning, setup, implementation, tests, and documentation. The assistant generated the large majority of the initial code (approximately 95 percent); the candidate must review and understand it before submission and the live walkthrough. No additional human collaborator or delegated coding subagent was used.

Runtime results are produced only by local Ollama: qwen2.5:1.5b for triage, qwen2.5:1.5b for final drafting (initial trials used llama3.2:3b), and nomic-embed-text for embeddings. The coding assistant's exact served model identifier is not exposed in the repository; it is distinct from these runtime models. No hosted inference API is part of the application.

One assistant mistake was assuming localhost would reach the IPv4-only Docker port mapping promptly on this Windows setup. The application connection stalled while an explicit 127.0.0.1 probe succeeded. We changed the default database URLs to IPv4 and added a ten-second connection timeout. Database activity inspection and a direct psycopg probe caught the issue before claiming a successful demo.

Another implementation lesson: a Git push dry-run cannot validate the branch before the first commit exists. It returned a missing-ref error; stored GitHub account discovery and the actual start push established access instead.

Evaluation metrics and JSONL outputs are generated by application commands, not authored by the coding assistant. Fake-model output is confined to automated tests and is not represented as real model evaluation.

A real initial draft also invented a packaging requirement and requested an order ID already present. The original citation checker did not establish semantic grounding. We inspected the pending text, superseded those unapproved drafts with an automated audit event, and added an extractive factual renderer plus a regression test. Human approval was requested separately for the revised text; the coding assistant did not approve it on its own.

The later focused refinement addressed unsupported `other` requests and ambiguous injection flags. New tests use synthetic requests and adversarial/benign examples rather than copied golden ticket IDs. Earlier evaluation files were preserved unchanged in eval/baseline-adb61a5. New results are generated from fresh model calls; evaluation may reuse public retrieval context but never model answers or decisions.
